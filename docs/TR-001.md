## Abstract

This report documents the first two development phases of a TinyML-oriented embedded systems project based on an ESP32 DOIT DevKit V1 and a commercially labeled MPU-6050 IMU module.

Phase 1 established low-level I2C communication, confirmed device identity through direct register interrogation, and validated raw accelerometer data acquisition without vendor libraries. Unexpectedly, the sensor returned WHO_AM_I = `0x72` instead of the MPU-6050 standard value of `0x68`, indicating a pin-compatible replacement device.

Phase 2 extended the firmware to include full 6-axis acquisition (accelerometer and gyroscope), offset calibration, scale conversion to physical units (m/s² and °/s), and a modular code architecture separating hardware logic from the main application loop. An OLED display integration attempt was conducted and documented as a hardware failure due to a defective unit.

---

## 1. Introduction

TinyML applications depend on reliable, calibrated sensor pipelines. Before collecting training datasets or developing inference models, the sensing subsystem must be fully validated at every layer: physical connections, communication protocol, register behavior, scale factors, and noise characteristics.

This report covers:

- I2C bus validation and device identification
- Accelerometer and gyroscope register characterization
- Offset calibration and scale conversion
- Firmware modularization
- OLED display integration attempt and diagnosis
- I2C diagnostic tooling

### 3.2 I2C Bus

Pull-up resistors (10 kΩ) were added between 3V3 and SDA/SCL lines during OLED integration attempts. These were removed after confirming the OLED was defective and the IMU operates reliably without them on the current protoboard configuration.

Note: the protoboard used showed partial rail failures during testing. IMU placement was validated by I2C scan before proceeding.

## 4. Phase 1 — Initial Hardware Characterization

### 4.1 I2C Bus Validation

An I2C address scan confirmed device presence at `0x68`.

### 4.2 Device Identification

| Register | Expected (MPU-6050) | Observed |
|---|---|---|
| WHO_AM_I (`0x75`) | `0x68` | `0x72` |

The device is not a genuine MPU-6050. It is likely a pin-compatible InvenSense/TDK-family replacement. Despite this, the register map — including power management, configuration, and data output registers — behaves identically to the MPU-6050 specification.

### 4.3 Power Management

| Register | Initial value | Action |
|---|---|---|
| `0x6B` | `0x40` (sleep) | Write `0x00` to wake |

Bidirectional register access confirmed.

### 4.4 Configuration Registers

| Register | Value | Interpretation |
|---|---|---|
| ACCEL_CONFIG (`0x1C`) | `0x00` | ±2g range (default) |
| GYRO_CONFIG (`0x1B`) | `0x00` | ±250°/s range (default) |

Both sensors operate at default sensitivity. No configuration changes were required.

### 4.5 Raw Accelerometer Data

Registers `0x3B`–`0x40` read directly via I2C.

**Representative raw values (stationary):**

| Axis | Raw value |
|---|---|
| AX | −1876 |
| AY | 524 |
| AZ | 17556 |

## 5. Phase 2 — Firmware Modularization and Full 6-Axis Acquisition

### 5.1 Code Architecture

The firmware was refactored into a modular structure:

| File | Role |
|---|---|
| `src/main.cpp` | Initialization and main loop |
| `src/imu.cpp` | IMU hardware logic |
| `include/imu.h` | Public interface declarations |
| `tools/i2c_scan.cpp` | Standalone I2C diagnostic tool |

This separation isolates hardware dependencies and simplifies future extension (additional sensors, filtering, inference).

### 5.2 Gyroscope Data Acquisition

Gyroscope output registers `0x43`–`0x48` were read and confirmed functional.

### 5.3 Scale Conversion

| Sensor | Range | Scale factor |
|---|---|---|
| Accelerometer | ±2g | 16384 LSB/g |
| Gyroscope | ±250°/s | 131 LSB/°/s |

Accelerometer output converted to m/s²: `(raw - offset) / 16384 × 9.81`  
Gyroscope output converted to °/s: `(raw - offset) / 131`

### 5.4 Offset Calibration

A 200-sample stationary calibration routine computes per-axis offsets. The AZ offset subtracts 1g (16384 LSB) to account for gravity.

**Representative calibration result:**

| Parameter | Value |
|---|---|
| Offset AX | −1411 |
| Offset AY | 467 |
| Offset AZ | 1261 |
| Offset GX | 185 |
| Offset GY | 355 |
| Offset GZ | −103 |

### 5.5 Calibrated Output (stationary)

**Accelerometer (m/s²):**

| Axis | Typical value | Noise range |
|---|---|---|
| AX | ≈ 0.000 | ±0.060 |
| AY | ≈ 0.000 | ±0.050 |
| AZ | ≈ 9.810 | ±0.080 |

**Gyroscope (°/s):**

| Axis | Typical value | Noise range |
|---|---|---|
| GX | ≈ 0.000 | ±0.350 |
| GY | ≈ 0.000 | ±0.350 |
| GZ | ≈ 0.000 | ±0.320 |

Accelerometer noise is consistent with MEMS behavior at ±2g range. Gyroscope noise is within expected limits for ±250°/s range without digital filtering.

## 6. OLED Display Integration Attempt

A DST-015 OLED display module was connected to the I2C bus (GPIO21/GPIO22) with the intent of displaying real-time sensor data.

**Findings:**

- The unit did not appear in I2C address scans (neither `0x3C` nor `0x3D` detected).
- When connected, the unit caused complete I2C bus collapse (Error -1 on all transactions), preventing IMU communication.
- The failure persisted with pull-up resistors (10 kΩ) on SDA and SCL.
- The failure persisted with VIN (5V) instead of 3V3 as supply.
- Connecting only VCC and GND (no SDA/SCL) still caused bus collapse, indicating an internal short circuit in the display module.

**Conclusion:** The OLED unit is defective. OLED integration is deferred pending replacement hardware.

---

## 7. Diagnostic Tooling

A standalone I2C bus scanner was implemented as a separate PlatformIO environment (`[env:i2c-scan]`) using a dedicated source directory (`tools/i2c_scan.cpp`). This allows bus diagnostics without modifying the main firmware, and serves as a reusable hardware validation tool.

---

## 8. Key Findings

- The IMU is not a genuine MPU-6050 (WHO_AM_I = `0x72`) but is fully register-compatible.
- Default configuration registers (ACCEL_CONFIG, GYRO_CONFIG) confirm ±2g and ±250°/s ranges.
- All 6 axes are operational and calibrated.
- Calibrated accelerometer output at rest: AX ≈ AY ≈ 0 m/s², AZ ≈ 9.81 m/s².
- Calibrated gyroscope output at rest: GX ≈ GY ≈ GZ ≈ 0 °/s.
- The protoboard has partially failed rails; IMU placement must be validated before each session.
- The OLED display unit is defective and excluded from the current configuration.
